Build from source ↗

Early software. Yours to explore. Used on one maintainer's Mac. Source builds are available; there is no signed download yet. See what has been verified.

A few ways to get things done.

Speak, or keep it typed.
Hold the talk key and ask, or type in the panel. Apple's on-device speech recognition turns your voice into text.
Work with your files.
Read files, write drafts and run commands. Benji's approval rules ask before destructive or outward-facing actions.
Ask about your screen.
Attach one screenshot to your next message. Benji can explain what it sees and point at a control.
Choose your model.
Bring your own provider key or connect a local model. Anthropic is the main live-tested path; other providers are not live-tested.

Background jobs are experimental. Browser reach, app offers and newer display features are not live-tested. The README status table keeps the details in one place.

Start with the source.

Benji is a Mac app with a Swift interface and a Python engine. The engine uses only Python's standard library.

The app requires macOS 14 or later. Source builds need Python 3.11 or later, Xcode 26 or later on a supported build Mac, and a model provider or local model.

The README walks through building the app, choosing a model and optional permissions. Provider usage may cost money; Benji doesn't include model credits.

Before you try it.

What leaves my Mac?

On-device speech recognition handles transcription. Your chosen model provider receives your requests and tool results, plus screenshots you choose to attach. Web searches and page fetches also contact those sites. See the privacy details for each path.

How much control does it have?

Benji can change files and control apps when allowed. Approval rules run in code, but they are not a sandbox. Read what you approve and leave command-line auto-approval off. Read the safety limits.

Can I help without writing code?

Yes. Try setup on another Mac, improve a confusing instruction, report a reproducible problem or help with a real demo. The contribution guide explains the process.

A small project.
Room for your contribution.

One maintainer, a public codebase and useful work to pick up. Start with an issue, keep the change focused, and say what you checked.
